# RDMA guided visualization audit

Implementation review for the unified guided-navigation redesign. The audit uses the authored Foundations V2 and Operations V2 specifications as content authority; it does not introduce replacement curriculum content.

## Audit method

Every authored subsection was reviewed against the visualization-quality questions in the assignment. The implementation decision is one of retain, simplify or restructure. “Recorded” means actual captured laboratory evidence; “source-derived” means a faithful reconstruction of application-constructed state from immutable source lines; “conceptual” means explanatory illustration. Optional detailed inspection remains available only behind subdued disclosures and does not alter the primary guided stage.


## Cross-cutting implementation notes

- Primary visual action buttons, reset controls and mode selectors were removed from the default teaching path. Visuals now render externally supplied guided stage state through `useGuidedVisualStage()`.
- Packet row selection and checksum/detail controls remain only as optional technical inspection or advanced exploration affordances. The guided stage selects and highlights the relevant packet automatically; optional inspection does not mutate the guided stage.
- The ordinary WRITE target-completion prediction remains optional. The Next action can reveal the recorded observation without an answer, and post-observation selections are explicitly labelled review rather than pre-observation predictions.
- Lesson-level guided state is persisted by stable step identifiers with a versioned revision. Legacy Foundations V2 completion is preserved where it has a meaningful correspondence; operations progress is restarted because the internal visual-state model changed.
- Conceptual illustrations remain visually and textually separated from recorded packet, completion, source-line and memory evidence.

## Cross-cutting consistency decisions

- The CPU remains a recognizable physical execution resource; kernel and application are software layers that execute on it rather than separate physical processors.
- Application memory remains a stable logical byte range across allocation, copy, registration and operation construction. Registration reveals metadata about the same buffer rather than redrawing it as copied memory.
- Work Requests, packets, completions, transport acknowledgements and control messages use distinct labels and directional arrows.
- Recorded evidence remains visually and textually distinguishable from source-derived and conceptual illustrations. Evidence bundle hashes are unchanged.
- Internal visualization controls were removed from the default guided experience. Optional answer selection for the WRITE target-completion reflection remains secondary and does not control progression.
- `Previous` reverses the same ordered state sequence, including subsection boundaries; refresh restores the persisted stable step identifier.
